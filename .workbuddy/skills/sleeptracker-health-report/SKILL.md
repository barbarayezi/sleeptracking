# Sleep Tracker 健康分析报告

这套报告的价值**不在于省时间，在于保住质量下限**。没有它，换个会话重新生成，大概率退化成"建议早睡、多喝水"的健康 App 模板话术——那对这个用户毫无意义，甚至是冒犯。

## 何时激活

- 用户要求生成/更新分析报告
- 用户问"最近数据怎么样""有什么趋势"
- 用户记录了梦境并希望被解读
- 阶段性复盘（通常间隔数天到一周）

---

## 第一步：理解这个项目到底在做什么

写任何一个字之前，先内化项目的根本动机（见 `AGENTS.md` 结尾）：

> 突破性认知推导 → 推无可推 → 抑郁焦虑 → 免疫系统过度激活 → 睡眠结构破坏、早醒、体重上升 → 将身体症状转化为结构化数据 → 量化分析 → 打破应激循环。

**把身体从"正在发生在我身上的事"变成"一个我可以分析的对象"——这是主体性的重新拿回。**

这决定了报告的一切基调：用户不是在寻求安慰，是在寻求**可被检验的结构**。

---

## 第二步：取数

服务在 `61023`，用 socket 直连或 Flask test_client（**curl 会被沙箱代理拦成 502**，详见 `sleeptracker-ops`）。

| 数据 | 接口 |
|---|---|
| 睡眠记录 | `GET /api/records?from=&to=` |
| 快速统计 | `GET /api/stats` |
| 饮食 | `GET /api/meals?from=&to=` |
| 经期 | `GET /api/periods` |
| 多维总览（按日 JOIN） | `GET /api/health-overview?from=&to=` |
| Whoop 每日指标 | `GET /api/whoop/daily` |
| Whoop 训练 | `GET /api/whoop/workouts` |
| 苹果健康步数 | `GET /api/healthkit/metrics?type=steps` |

**优先用 `/api/health-overview`** —— 它已经按日把所有维度 JOIN 好并附带关联洞察，比自己拼接可靠。

数据接口偶尔需要 10~12s（Turso 云偏慢 + waitress 队列），耐心等，不要误判为失败。

**必读上一期报告** —— `reports/` 目录下最新的那份。报告是连续的，新报告要衔接旧报告的根因链版本号和未竟议题。

---

## 第三步：归档规范

```
reports/YYYY-MM-DD-analysis.md
```

文件头固定格式：

```markdown
# 睡眠分析报告 — 2026-07-16

> 数据范围：2026-06-29 ~ 2026-07-16（21 条记录）
> 分析时间：2026-07-16

---
```

章节用中文数字（一、二、三……），子章节用 `### 1.1` 形式。章节之间用 `---` 分隔。

---

## 章节骨架

不必每期全用，但**顺序不要打乱**。日常复盘用一至五 + 后续行动；有重大事件或深度对话时才展开深度讨论。

| 章节 | 内容 | 是否必需 |
|---|---|---|
| 一、数据总览 / 新增数据 | 记录表格（ID·醒来日·类型·入睡→醒来·时长·质量·问题）+ 健康指标 | 必需 |
| 二、本期关键事件 | 就医、用药、急性发作、重大生活变化 | 有则写 |
| 三、可观察的趋势 | 分维度：睡眠质量 / 午睡 / 体重 / 步数 / 喝水 / 恢复分 | 必需 |
| 四、数据中可见的关联 | 跨维度交叉，例如步数↔睡眠、饮食↔早醒 | 必需 |
| 五、与上期报告的延续 | 上期预测是否成立、议题进展 | 必需 |
| 六、深度讨论 | 由用户对话延伸出的认知/哲学/结构性议题 | 有则写 |
| 七、梦境分析 | 内容全文 → 逐层拆解 → 和现实的对位 → 结论 | 有则写 |
| 八、根因链（vN） | 代码块画因果链，标注 vN→vN+1 的核心变化 | 有更新则写 |
| 九、后续行动 | 🔴/🟡/🟢 三级优先级表格 | 必需 |
| 十、数据质量说明 | 缺失、口径、可信度边界 | 必需 |

## 病史时间线（写作时必须知道的背景）

- **7/13** — 耳石症复发，叫了 120 急救
- **7/14** — 就医；父亲鼾声干扰睡眠环境
- **7/15** — 首次服用抗抑郁药物
- **7/16** — 药物第二晚，用户评价"感觉没用，效果跟我吃镁没啥区别"
- 长期模式：午睡几乎全部 `average` + `insomnia`——**自主神经无法切换到放松状态**，这是核心观察指标
- 神经类型：阿斯伯格。历史报告用它解释"内部时间流速比外界快"

**⚠️ 数据断层：** `sleep_records` 曾被整表清空过一次（约 7 月底），从 Whoop 只回填到 2026-07-22 之后。7/8 和 7/15 报告里引用的更早记录**在数据库里已经不存在了**。写新报告时若引用早期数据，要注明来源是历史报告而非当前库，不要假装还能查到。

## 根因链的演化（不要重置版本号）

已经推进到 **v3**：

- **v1** → 应激循环、习得性无助
- **v2** → 认识论裂缝：第一人称观测被第三人称框架否定（反笛卡尔定位）
- **v3** → 时间流速差异：不是两个框架不兼容，是她的内部时间流速太快，外部世界的演化速度跟不上

核心隐喻是**"搭桥"**：标准化 + 可复现 + 可翻译 + 可共享。桥不是为了"说服"或"改变"什么，而是**让时间差可见**。

新报告如果推进了根因链，写成 v4 并明确标注 v3→v4 的核心变化是什么。

---

## 叙事基调（最容易做错的部分）

**要这样写：**

- 直接给结论，用数据支撑。"入睡时间从 22:30 漂到 00:30，睡眠缩到 7h" 这样的具体事实
- **区分表面相同、机制不同的现象**。例：7/9 是"逻辑战斗停不下来"（焦虑驱动的熬夜），7/16 是"看剧看嗨了"（放松驱动的停不下来）——结果都是晚睡 2 小时，但**成因完全相反**，不能混为一谈
- 大段引用用户自己的原话，用引号标出。她的自述是一手观测数据，比任何推断都可靠
- 承认不确定性和数据边界，不要为了叙事完整去填补空白
- 结构性批判是允许且被期待的（医疗体系的"门槛逻辑"——只对终点事件反应、忽略过程信号；医患权力结构——平等位被读作挑战）
- 哲学讨论可以走得很远（量子力学 vs 相对论、四维静态块与自由意志、平行世界模型）。这不是跑题，这是项目的一部分

**不要这样写：**

- ❌ "建议保持规律作息""多喝水有益健康"——泛泛的健康建议
- ❌ 居高临下的安抚、"别担心""会好起来的"
- ❌ 把抑郁焦虑当成需要被"纠正"的错误，而不是需要被理解的信号
- ❌ 回避尖锐结论。用户要的是真实的推导，不是让人舒服的版本
- ❌ 用第三人称医学话术盖过她的第一人称体验——这正是报告批判的东西

## 后续行动表格格式

```markdown
| 优先级 | 行动 | 说明 |
|------|------|------|
| 🔴 | 抗抑郁药继续满2-4周 | 排除"药物类型不对"变量 |
| 🟡 | 午睡作为核心指标 | 午睡恢复good = 真正的拐点 |
| 🟢 | 不找"同类" | 桥搭得够远，就能被看到 |
```

🔴 立即 / 🟡 观察 / 🟢 长期。**说明栏要写清楚"为什么"，不只是"做什么"。**
